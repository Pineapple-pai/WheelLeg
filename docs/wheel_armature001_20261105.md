# 改装M3508轮侧惯量查询、计算边界与0.001候选

用户提供的组合为改装减速箱配M3508转子：587rpm空载、571rpm额定、2.46N·m额定、24V/10A、336.4g。当前项目与固件沿用减速比268/17≈15.7647。本轮保留该比值；图片本身不包含齿数，不能仅凭参数表确认齿轮结构。

## 查询与可计算部分

查询了DJI原装M3508 P19官方手册及改装箱相关资料，未取得这套组合的裸转子惯量、各级齿轮/行星架惯量或整套输出侧实测惯量。公开网页中的同名参数、其它电机惯量或仿真论文取值不能直接作为这套改装总成标定值。

[DJI原装P19官方手册](https://rm-static.djicdn.com/robomasters/public/document/RoboMaster%20M3508%20P19%20Brushless%20DC%20Gear%20Motor%20V1.0.pdf)的参数与用户图中改装总成不同。手册给出减速比3591/187、机械时间常数49ms、速度转矩梯度72rpm/(N·m)，但没有直接给出裸转子惯量。

能做一个**有条件的原装总成估算**：假设一阶线性定电压电机模型成立、时间常数和转速转矩梯度对应相同轴侧与相同动态条件，且忽略会混入该时间常数的其它损耗/控制动态，则：

`J_stock,eq ≈ tau_m / |dω/dT| = 0.049 / (72×2π/60) ≈ 0.006499 kg·m²`。

如果再强假设全部惯量都按输入侧等比例折算，换成268/17后约为`0.006499×[(268/17)/(3591/187)]²≈0.004380kg·m²`。**这不是改装组合的已知惯量**：原装总成中的齿轮惯量无法从裸转子中拆分；改装齿轮和行星架的自转/公转惯量、损耗及测试控制定义都未知。因此不能把0.004380当作应直接写入模型的准确值，也不能凭它证明0.01或0.001谁更接近实机。

真实折算需按内部运动部件的动能计算：`J_eq,out=2T_internal/ω_out²`。仅裸转子贡献是`n²J_rotor`，齿轮与行星架还需另计。336.4g含不旋转外壳、定子等，不能把整套质量按一个实心圆柱计算。最大效率70%也不能直接乘除惯量。

## 按用户授权采用0.001

准确值不足时按指定方案，将左右轮joint armature均设为**0.001kg·m²**，明确标记为待标定工程候选，不是厂商实测值。它是轮侧附加惯量；轮子本体的CAD惯量仍在body inertial中，不能重复加入armature。MuJoCo该字段的定义见[官方说明](https://mujoco.readthedocs.io/en/3.3.6/XMLreference.html#body-joint-armature)。

作为轴侧换算检查，若把0.001全部归给转子，反推`J_rotor=0.001/(268/17)²≈4.024e-6kg·m²=4.024kg·mm²`。这只是等效换算，不代表已测得M3508转子惯量。

默认模型改为`models/uz05_20261105_armature001/uz05_rl.xml`，原始`models/uz05_20261104/uz05_rl.xml`保持原字节，历史权重继续可复现。网格共享原版本目录，避免资源副本。

仅改变左右轮armature，云台惯量/COM、其它关节惯量、轮轴阻尼0.02、轮径、电机限流和A映射、奖励及动作接口均保留。当前默认的训练输出名称改用armature001标记，主shell入口的默认版本带时间戳，不会继续使用原始新版训练名称。

## 后续训练结论（2026-11-06）

下面的从头试训命令保留作历史说明。随后实际1000轮仍在3秒起步前倒地，不能据此推荐继续从头长训。现已实现并审计显式跨模型参数初始化，成熟v16初始化在当前0.001物理下恢复站立与双向低速姿态覆盖，但速度精度未全面通过。当前入口与验收边界见[最新训练说明](armature001_transfer_training_20261106.md)和[复盘报告](../diagnostics/armature001_training_review/report.md)。

## 验证与使用边界

新旧模型的语义XML逐项比较，除两个轮轴armature和资源路径外相同；验证共享网格存在。单测同时检查旧0.0001和上一版0.01的模型哈希不能被轮电机适配开关绕过。历史warmstart测试显式选择原0.01模型，避免把跨模型迁移当普通续训。

验证产物位于`diagnostics/armature001_validation/`。实际PPO链路检查只运行2环境×16步×2轮=64个转移，验证子进程采样、优化、保存和新契约，不作为学习效果。固定旧策略评估显式属于跨模型诊断，不代表旧checkpoint已获准作为新模型直接续训来源，也不能将存活视为速度精度合格。

以往`train_joint_startup.sh`、`train_joint_precision.sh`和`train_joint_refine.sh`的默认SOURCE来自0.01模型；在当前默认0.001上会被契约正确拒绝。复现历史实验应显式选择原XML。新模型基础阶段如需从头开展独立试训，可使用以下命令（本轮没有执行该25轮训练）：

```bash
unset UZ05_MODEL_XML
FROM_SCRATCH=1 VERSION="joint_startup_armature001_$(date +%Y%m%d_%H%M%S)" \
  bash scripts/train_joint_startup.sh --updates 25 --save-interval 25
```

若要复用已有成熟策略，需要另行明确跨模型初始化并完成审计，不能改写旧模型哈希冒充同模型，也不能直接从高惯量训练结果推断本版本已通过站立或起步。

本轮实际结果：18项相关单测通过；双进程PPO链路64步完成。固定旧策略下站立与+2m/s起步各3/3存活24秒；-2m/s起步与后退停车均0/3，高速换向也未通过。+2末段实际约1.768m/s，尚未满足5%跟踪。完整结果见[验证报告](../diagnostics/armature001_validation/report.md)。这说明0.001候选恢复了该固定策略的部分正向能力，但不是反向控制的已验证修复。
