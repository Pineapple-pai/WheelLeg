# 实物 fast_samples 数据检查

原始数据：`/home/p/文档/fast_samples.csv`；采集摘要：`/home/p/文档/fast_summary.json`。
用户说明：跑步/转弯记录，力矩来自电机反馈，角度/速度单位尚待确认。
只分析数据，未覆盖原始文件，也未据此修改 MuJoCo 物理或执行器参数。

## 结论

这批记录足以检查采样时间、编码器位置/速度一致性、转弯覆盖以及反馈力矩分布。
它可以作为后续辨识的运动数据，但目前不能据此给出可信的整车惯量、电机力矩常数、
执行器延迟或关节位置环/轮速环参数。缺失的输入与姿态、负载条件需要补齐。

## 单位交叉检查

对每个电机做互不重叠的25间隔窗口（通常约0.1s），比较位置增量与按t_ms积分的速度。
只用速度积分绝对值大于0.005的窗口；未插值或修补原始数据。

| 电机 | 位置增量 / 速度积分拟合斜率 | 相关系数 |
|---|---|---|
| 左轮 | 1.01265 | 0.999926 |
| 右轮 | 1.00768 | 0.999939 |
| 左前关节 | 0.99580 | 0.995507 |
| 左后关节 | 0.99420 | 0.995324 |
| 右前关节 | 0.99903 | 0.996036 |
| 右后关节 | 0.99570 | 0.994560 |

这支持速度是对应位置每秒的变化率。如果位置为rad，电机速度就是rad/s，轮速字段不是m/s。
仅靠这个比例不能证明编码器读数属于减速器前还是后，也不能排除位置和速度同时采用了同一个错误缩放。
需查看生成CSV的固件与采集器确认轴侧和单位。

若假定轮速是轮轴rad/s、轮半径0.055m，且安装符号与参考固件相同，可以构造
`v_roll_proxy = 0.055*(wheel_right_speed-wheel_left_speed)/2`。
该代理量1%/99%分位为−1.720/+1.813m/s，绝对峰值3.178m/s，绝对值超过2m/s的样本约0.97%。
它不含腿部运动、姿态和轮滑移修正，不是独立车身速度，不能据此声称实车达到3.18m/s，
也不能据此计算速度跟踪误差。车身正向符号仍需实测确认。

## 当前能够与不能够辨识的内容

- 可以：检查时间质量、位置/速度标度一致性、运动覆盖、反馈分布，筛选后续机械灰箱拟合片段。
- 有条件：若反馈力矩标度可信，且有正确几何、初始状态、基座运动和负载信息，可把反馈力矩
  作为机械系统输入；不一定要求所有机械辨识都必须使用发送指令。
- 目前不能：由反馈力矩单独辨识命令到力矩的延迟/电流环动态，或辨识尚未实现的位置环/速度环。
- 目前不能：只靠六电机和三个角速度，可靠拆分整车质量、质心、惯量、摩擦与接触参数。
- 目前不能：确认前后速度跟踪偏差、实际腿长差、绝对pitch或真实轮滑移。需要相应目标、零位映射和独立测量。
