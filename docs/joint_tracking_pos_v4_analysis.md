# v4：5000 轮训练分析与 MuJoCo 回放

本轮从随机 PPO 权重开始，训练 20,480,000 个采样步，耗时约 1 小时 30 分钟。
使用固定权重、固定 1e-4 学习率、固定 0.001 熵系数，未使用课程或退火。
此次只分析已有模型和生成回放，没有修改训练参数或模型权重。

结论：相对 v3，恢复了大部分平衡与跟踪能力，同时比 v2 显著减少输出变化和力矩饱和。
但固定命令测试仅 148/180 跑满，弱于 v2 的 180/180；零命令位置/航向保持、长时间固定前进尚未达标，
不能只因 reward 与 episode length 较高而宣布成功。

最后一步 KL=0.0175、clip fraction=18.65%、explained variance=0.922；
这些指标支持优化过程仍在正常更新，但不能替代物理任务验收。

v4 每步正奖励上限为 9.5，满 1500 步的正奖励总和上限为 14250。
最后滚动窗口的回报/步数约 8.06。高回报既来自回合较长，也来自单步任务得分较高。
**v2/v3 的正奖励上限为 7.5，因此不能直接用总 reward 大小跨版本比较性能。**

## 随机变命令复测

使用独立种子 30000–30009，命令分布及重采样方式与训练相同；
保留观测噪声、名义动力学，每回合上限 12 秒。

| 动作方式 | 跑满回合 | vx MAE (m/s) | yaw MAE (rad/s) | 高度 MAE (cm) | 轮速目标变化 RMS (rad/s) |
|---|---:|---:|---:|---:|---:|
| 确定性 | 10/10 | 0.04199 | 0.10851 | 0.551 | 1.364 |
| 采样动作 | 10/10 | 0.04505 | 0.11195 | 0.633 | 1.630 |

这 20 个测试回合全部跑满，是相对 v3 的明确改善；样本仍不足以宣称全面可靠。
同组种子的 v2 确定性回放为 9/10 跑满、轮速变化 RMS 7.22 rad/s。
v4 的确定性轮速变化降低约 81%。

v4 四关节力矩饱和比例分别约 42.63%、25.13%、36.61%、27.51%，平均约 32.97%；
v2 同类测试约 82%–86%。输出质量明显改善，但其中部分关节仍超过 30% 的目标。
轮电流饱和比例约 28.74%（确定性）或 35.86%（采样动作），也需要继续观察。

**零命令站定仍未合格。** 确定性随机测试中，零命令片段最大平面漂移约 23.31 cm，
最大航向误差约 26.52°，只有约 71.15% 的零命令采样在 5cm 内。
采样动作对应约 13.02 cm、25.38°、78.92%。这些零命令片段含从运动切换到停止的过程。
不能用低平均速度误差替代位置和航向保持，也不能把“没有倒下”解释成“站定”。

```bash
bash scripts/replay_joint_tracking.sh \
  --checkpoint checkpoints/joint_tracking_pos_v4/checkpoint --case suite
```

本次尚未验证速度全范围边界、域随机化、长期运行和实机。固定命令长期保持与训练的
2–5 秒运动命令保持时间不同，必须单独验收，不能用随机命令测试成功代替。

## 完成的 180 回合固定命令评估

高度 0.245/0.270/0.295m；六种固定命令；每工况 10 个配对种子 20000–20009。
前进/倒退为 ±0.3m/s，旋转为 ±1rad/s，组合为 vx=+0.3、yaw=−1；每回合最长 12 秒。
**148/180 跑满，存活率 82.22%。**

| 工况 | 跑满回合 | vx RMSE (m/s) | yaw RMSE (rad/s) | 高度 RMSE (cm) |
|---|---:|---:|---:|---:|
| 零命令 | 29/30 | 0.0355 | 0.0869 | 0.562 |
| 固定前进 | 1/30 | 0.1268 | 0.1751 | 1.184 |
| 固定倒退 | 28/30 | 0.1293 | 0.1630 | 0.686 |
| 原地旋转 | 60/60 | 0.0429 | 0.2009 | 0.966 |
| 平移加旋转 | 30/30 | 0.0872 | 0.2736 | 1.089 |
| 综合 | 148/180 | 0.0846 | 0.1924 | 0.922 |

误差包括起步瞬态，并按实际存活采样步数加权；提前失败后不继续累积误差，必须与存活率一起看。
特别是固定前进，三个高度分别只有 1/10、0/10、0/10 跑满。高度 0.27m 的平均存活约 9.21 秒，
0.295m 约 7.45 秒。随机运动命令只保持 2–5 秒，因而随机测试跑满不能覆盖此项长时间稳定性。

对照 v2 同工况的 180/180、vx RMSE 0.0588、yaw RMSE 0.0832：v4 的固定命令鲁棒性和
速度跟踪**存在回退**，不能宣称本轮在所有指标上更好。高度精度则从约 1.285cm 改善到 0.922cm。

### 执行器和姿态

本组固定命令测试的轮速变化 RMS 约 1.370 rad/s，四关节力矩饱和比例约
43.74%、32.16%、40.73%、31.42%，说明大幅减少高频饱和并未自动带来长期平衡。
姿态几何合格采样比例约 99.984%；最大瞬时前后错位约 16.79cm，包含失稳时的异常瞬态。
不能把末帧 Posture 日志替代整个回合的姿态检查。

代表性前进失败（种子 20000、高度 0.27m）：第 1241 步，即 9.928 秒，
机身高度降至约 0.224m，pitch 约 −25.47°；接触记录明确包含地面与机身碰撞体，
触发 `body_contact`。这是实际物理失稳，不是显示问题或只触发一个无关软件限位。
[失败接触记录](../logs/joint_tracking_pos_v4_forward_failure.json)保留相关数据。

### 下一步判断

本轮改动解决了 v3 的明显低存活退化，并取得输出变化和饱和的实际改善，但整体任务仍未合格。
下一步优先定位长时间恒定前进失稳，以及高姿态的零命令位置/航向保持。
建议用这些独立指标选 checkpoint，不以总 reward 或平均 episode 长度单独选模；
不建议只延长当前配置训练后就假定这些问题会自行消失。

[完整固定命令评估](../logs/joint_tracking_pos_v4_eval.json)含逐回合终止原因、误差、姿态和输出统计。

```bash
conda run --no-capture-output -n sim python scripts/eval_joint_tracking.py \
  checkpoints/joint_tracking_pos_v4/checkpoint --episodes-per-case 10 \
  --output logs/joint_tracking_pos_v4_eval.json
```
