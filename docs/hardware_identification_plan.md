# 实物代码审阅与 MuJoCo 参数辨识方案

审阅日期：2026-11-03。参考工程：`/home/p/文档/aboard/aboard`。
用户确认该工程与实车接近，但实车另有改动。本报告描述参考源码，不代表已核实当前烧录固件。
本次未修改固件、执行器参数或训练配置，也没有连接、烧录或运行实物。

## 先确认的结论

- `CMakeLists.txt:47` 起编入 board_comm、vmc_probe、vmc_math、hi12_imu 和 RTT 模块。
  工程目标 STM32F427xx，自身定义为 A 板底盘；另一板状态/遥控通过 UART8 交换。
  `docs/硬件配置.md` 的 CAN 板间通信描述已与源码不同。
- `App/Inc/vmc_probe.h:10` 定义左轮反馈 0x202、右轮 0x201，文档写法相反。
  左轮输出方向 -1，右轮 +1；物理侧、CAN ID、反馈符号、发送符号应分别记录。
- 关节通过 `can_send_joint_torque()` 发送 MIT 指令，p/v/kp/kd 全部为零，仅力矩非零。
  这不是 PPO 关节位置执行环。轮端发送 0x200 电流帧，当前控制路径不是 PPO 轮速环。
- 原生 LQR/VMC、重力补偿、roll 补偿、航向保持、云台跟随和状态保护会改变最终电机输入。
  整车辨识应记录最终实际发送命令，并标记这些模块的使能与输出。

## 不能直接搬入仿真的参数

### 轮子力矩口径

参考固件将 C620 指令按 ±16384 对应 ±20A 换算，并使用 0.3Nm/A：

`motor->torque = given_current / 16384 * 20 * 0.3`

注释称其为电机轴力矩，发送端使用 2730.6666 raw/Nm，轮速除以 268/17。
这说明代码内部采用了特定力矩口径，不证明 0.3 是真实电机轴力矩常数；反馈电流字段的
标度也不能仅因发送端标度相同就视为已经实测确认。

仿真目前使用输出侧 0.246Nm/A，再乘效率 0.7，即有效 0.1722Nm/A，并有输出侧力矩限幅。
两边变量所属轴侧不同，禁止把这些数字直接相除作“修正倍数”。还要检查额定点推导出的
输出力矩常数是否已包含传动损耗，避免再次乘效率。

辨识时保留原始电流码、命令码和轮速 RPM。先用已知力臂和测力装置测输出侧等效
力矩/电流系数，分别覆盖正反向与左右轮，再决定是否拆分电机 Kt、减速比和效率。
只有速度响应且负载惯量未知时，通常不能单独确定 Kt 和惯量，应报告可辨识的组合参数。

### 达妙关节协议与零位

`vmc_probe.h:28` 起使用位置 ±12.5rad、速度 ±45rad/s、力矩 ±54Nm 协议范围。
这些是编解码范围，不是额定工作限制；必须核对当前 DM8009P 驱动固件配置。
关节位置反馈也不能看到减速比9:1就再除一次9，先确定驱动反馈的轴侧定义。

头文件 `:342` 起及 `tools/test_joint_calibration.py` 记录过右前关节在固定姿态重新上电后
出现约40°跳变。它是参考版本的历史记录，不是本次实物检测结论。
优先做固定姿态、重复断电上电测试，记录四电机原始位置、驱动状态和实际机械姿态。
若有跳变，先解决零位持久性、编码器/驱动配置或回零机制，再做运动学拟合。
不能用某一次读数重新设偏置后就认为问题消失。

左右腿长来自编码器、固定零位及五杆运动学计算，不是独立长度传感器真值。
需在多个受约束姿态实测髋轴到轮轴的空间距离，并与模型对齐；腿长和车身离地高度
是不同量，不能直接拿训练高度命令0.22–0.32m拟合固件腿长。

### 时间与 IMU 坐标

- `vmc_probe_task()` 使用 osDelay(1)，控制周期包含计算时间，不是严格1kHz。
  源码注释记载历史约450Hz；当前频率需重测，不能将注释当成本次结果。
  现有 loop_dt_us/loop_count 可复核平均频率和波动，记录原始时间间隔而非只记录限幅后的dt。
- MuJoCo 当前策略周期8ms，底层子步2ms。部署时要分清策略更新、执行环、CAN和IMU频率。
- 参考代码 pitch 取 angle_rad[1]，pitch_rate 取 gyro_radps[0]。
  可能涉及传感器输出坐标约定，不能仅凭下标判错。做单轴手动摆动，验证三轴角度、
  原始陀螺、符号、单位及安装变换；较大姿态时Euler角导数不直接等同于某一陀螺分量。

## 已有采集能力与不足

`App/Src/vmc_lqr_rtt.c`：VMCVOFA、schema10，名义20ms遥测，包含MCU时间、
控制周期/计数、LQR分项、滤波状态和部分电机输出。`Drivers/RTT/SEGGER_RTT_Conf.h`
设置64KiB上行缓冲，默认非阻塞跳过模式；缓冲满仍可能丢日志，需要序号/丢帧计数。

`tools/rtt_kalman_capture.py` 已支持 RTT Telnet/J-Link、原始采集和CSV报告，可复用。
它主要分析现有50Hz状态估计遥测，不能直接当作高频电机辨识记录器。
遥测调用发生在本循环最终关节和轮输出之前，有些输出字段可能对应上一周期。
此外CAN中断会异步更新数据，读取多个volatile字段并不保证同一采样快照。

建议新增独立辨识记录格式，保留原遥测兼容性：

| 分组 | 字段 |
|---|---|
| 帧头 | schema、固件版本/参数快照ID、seq、MCU采样us、真实dt、丢帧计数 |
| 实验 | 工况/激励ID、原目标、注入信号、使能/限幅/安全门控标志 |
| 各关节 | CAN ID、原始位置/速度/力矩反馈码、换算值、反馈接收时刻、最终MIT发送内容 |
| 各轮 | 编码器码、原始RPM、原始反馈电流、最终发送电流码、反馈与发送时刻/发送结果 |
| IMU | 原始acc/gyro/quat、融合角、接收时刻、计数、有效标志 |
| 辅助 | 已有时记录电压、温度、独立位移/速度及其时间戳 |

在确定的控制阶段生成一致快照，输入保持逐电机发送时间，不能把同一循环等同于所有输入同时施加。
控制任务只写记录环形缓冲，后台批量发送二进制帧，避免在控制热路径扩大格式化开销。
采样先覆盖实际控制周期；需要200–500Hz或更高取决于实测带宽与反馈频率，
轮/IMU重复读数不算新样本。先做带宽预算和丢帧检查，再确定最终记录率。

## 建议实验顺序

1. **版本和基线。** 获取与实车相符的最新工程和运行参数快照，记录电调型号及驱动配置。
   先导出一段普通LQR站立/低速日志，核对时间、单位、符号、收发反馈年龄。
2. **零位、几何、IMU。** 固定姿态重复上电；多个已知几何姿态对比两腿长度及前后构型；
   单轴摆动检查IMU坐标。任何零位不稳定先解决，再继续拟合。
3. **轮子单独实验。** 机体固定、轮子离地、左右分开做低幅正反向电流阶跃/多频输入，
   测延迟、摩擦、等效惯性响应；已知负载实验确定力矩标度。空转不能辨识地面摩擦。
4. **关节单独实验。** 固定机构或已知加载、避开奇异构型，记录重力负载与力矩响应；
   随后建立与MuJoCo一致的位置执行环，在多个角度和负载下验证响应。
5. **LQR整车闭环。** 保留稳定LQR，小幅共模/差模激励，覆盖不同高度、前进/后退和制动。
   保存完整输入链路，采用包含已知反馈控制的灰箱拟合或合适闭环辨识方法，
   避免将闭环指令到输出响应误认作裸机械模型。
6. **PPO执行接口。** 明确关节位置环和轮速环将运行在哪个控制器、固定哪些增益和限幅。
   用受约束实验校准这两条执行链路；LQR只用于前期实验，不混入最终纯PPO平衡动作。
7. **独立验证与回填。** 用未参与拟合的负载/方向/高度/电压数据比较短时预测及连续仿真，
   仅回填有数据支持的参数及不确定范围。未知的Kt、惯量、效率不能全部自由拟合。

独立车身速度参考对高速轮滑移辨识很重要：轮速推算的速度不能同时充当滑移真值。
没有外部速度测量时，可以先校准执行器和低滑移工况，把高速接触辨识标为待完成。
